# レーダー計測（非接触の呼吸・心拍）

79GHz 帯レーダー評価キット PTM RFR79ITR34-30U（TI IWR1843 搭載）で、座っている人の呼吸を 1 回ずつ測り、タイピング実験と一緒に記録する。心拍数も同じ信号から出す。

- デスクトップアプリ [app/](app/)（Tauri。Rust + TypeScript、Windows / macOS）: タイピング課題とレーダー計測を 1 つのアプリで行う
- Python スクリプト [vitals.py](vitals.py): レーダーだけを単独で記録する
- [report.py](report.py): 記録を図と要約にする

チャープ設定（[chirp.cfg](chirp.cfg)）と推定方法は、アプリと Python で共通。

## 用意するもの

- レーダー本体と USB Type-C ケーブル。給電も USB。同梱の DA ボードは使わない。
- ファームウェアは出荷時のまま（mmWave SDK 3.5 のデモ）。
- PC にはシリアルポートが 2 つ現れる（FTDI FT4232H）。現れない場合は FTDI の VCP ドライバを入れる。ポート番号の指定は要らない。

## 置き方

- レーダーは三脚とクランプで固定し、ケーブルも動かないように留める。ケーブルが揺れると USB 接続が切れる。切れても自動で繋ぎ直し、記録は続く。
- 体から 0.4〜0.8 m。測れるのは 0.3〜1.5 m。正面から水平に当てる。斜めだと反射が弱くなる。
- 上下方向のビームは ±10° ほどしかない。0.6 m 先で上下 ±10 cm。左右は ±50° ほどと広い。
- 胸に向ける場合は胸骨の高さに合わせる。机の上の手や腕がビームに入ると、呼吸がそちらの動きに埋もれる。
- 真横（肋骨の横）からは測れない。反射は 30〜33 dB と強いのに、呼吸ベルトと同じ周期の動きはどの距離にも映らなかった（下の「確認できていること」）。
- 背中に向ける場合は肩甲骨の下端あたり。腕が入らない代わりに、動きは 0.5〜2 mm と小さい。背もたれがメッシュや布なら通る。金属のフレームや厚い板は通らない。

## 動作確認の手順（アプリ）

1. [Releases](https://github.com/Suke-go/shinkokyu/releases) からインストーラーを取って入れる（Windows は `.exe`、macOS は `.dmg`）。署名はしていないので、初回は Windows なら「詳細情報 → 実行」、macOS なら右クリック →「開く」。
2. レーダーを繋ぎ、アプリを開いて丸いボタンを押す。輪が一周するまでの 10 秒はデータを溜めている。
3. 右上の 3 本のバーと、その下の 1 行で信号の質を見る。3 本そろうまで、じっと座ったままレーダーの高さと向きを直す。

   | バー | 状態 | 下の 1 行 |
   |---|---|---|
   | 0 本 | 測れる範囲（0.3〜1.5 m）に強い反射がない | 何も映っていません |
   | 1 本 | 強い反射はあるが、呼吸の動き（0.3 mm 以上）がない。椅子や壁を見ている | 物は映っていますが、呼吸の動きがありません |
   | 2 本 | 呼吸している人が映っているが、まだ追えていない | 体が動いています ／ あと少しそのままで |
   | 3 本 | 直近 30 秒に呼吸が 2 回以上区切れ、直近 10 秒で体が動いていたのが 2 割以下 | 安定しています。課題を始められます |

4. 画面のほかの表示。
   - 大きい数字: 直近 30 秒に区切れた呼吸の長さの中央値を、1 分あたりの回数と 1 呼吸の秒数で示す。線の縦線と同じ呼吸を数えている。薄い間はまだ安定していない
   - 小さい数字: 心拍数（毎分）。薄い間は信用できない
   - 線: 胸や背中のいまの動き（直近 30 秒）。レーダーのフレームごとに描くので、息を吸うとすぐ動く。ガウシアンで平滑化し、体の位置のゆっくりしたずれ（基線）を引いてあるので、姿勢が少し変わっても線は中央に戻る。ボタンを押して 1 秒ほどで流れ始める。薄い縦線が 1 呼吸の区切りで、波と一緒に流れる。濃い線は呼吸している人を追えているとき。この線は表示用で、記録には使わない
   - ボタンの上の帯: いまレーダーに映っているもの。左が近く（0.3 m）、右が遠く（1.5 m）で、濃いほど強い反射
   - 数字が「–」のままなら、人が映っていない
5. 安静時の呼吸は、丸いボタンの右のストップウォッチで測る。測定中に、3 本になったのを見て押すと経過時間が進み、もう一度押すと終わる。開始も終了も実験者が波形を見て決める。終えると、長さ・数えた呼吸の回数・1 呼吸の長さの中央値が下に出て、`rest_<日時>.json` として保存される。左上の時計の数字は長さの目安（分）で、− と + で変える（既定 3、0 で目安なし）。目安に達すると経過時間が太字になる。
   - この画面には呼吸の波形が出ている。参加者が自分の波形を見ると呼吸が変わりやすいので、安静を測る間は画面を参加者に見せない。
   - 安静を測ったら丸いボタンで測定を止め、続けてその人の課題を始める。集計（`export.py`）は、課題の開始前 1 時間以内で最後に測った安静を、その課題の安静として組にする。
6. 鉛筆のボタンでタイピング課題を開く。実験 ID（試すだけなら `demo-ja`）と参加者 ID を入れて進め、スタートを押す。
   - スタートの画面には、参加者へのお願いが出る。ふだんどおり入力してよく、同じ姿勢を保つ必要もないが、椅子を動かす・体を大きく前後に倒す・席を立つことは課題が終わるまで控えてもらう。
   - 課題に時間制限があれば（`taskA` は 20 分）、その時間で自動的に終了する。
   - 課題の入力画面では、下端の中央に最初の画面と同じ 3 本線が小さく出る。実験者はこれで、課題中も測れているかを見る。マウスを載せると理由が出る。
   - 最初の画面（波形と数字）は課題中も動き続ける。画面が 2 枚あれば、実験者側に置いておける。
7. 終わると、終了画面にこの PC の保存先と、課題中に「呼吸を数えられた時間」が出る（割合、回数、1 呼吸の長さの中央値）。その場で測り直すかどうかの目安にする。`sessions.csv` の `task_counted` と同じ量だが、こちらは測りながら数えた値なので少しずれる。じっと座って正面から測った 8 本では、記録後の計算で 64〜94% だった。

安静時の計測と課題は別々の記録になる。安静は最初の画面で丸いボタンを押して測った記録（`radar_<UTC 日時>.*`）の中の、ストップウォッチが動いていた区間。課題を開くと、レーダーは課題用の記録を新しく始める。

## 記録されるもの

すべて「ドキュメント/shinkokyu-radar」に残る。ネットワークがなくても記録は完結する。

| ファイル | 中身 |
|---|---|
| `typing_<セッションID>.json` | 課題のセッション（課題文、入力結果、時刻同期の結果）。実験サーバーの `data/<id>.json` と同じ形 |
| `typing_<セッションID>.events.jsonl` | 打鍵などの全イベント。レーダーの推定（`vital`）と 1 呼吸ごとの記録（`breath`）もここに入る |
| `radar_<セッションID>.json` | チャープ設定、フレームレート、セッション ID |
| `radar_<セッションID>.bin` | レーダーの全フレーム。固定長レコード: 到着時刻 `float64`（ms）、フレーム番号 `uint32`、IQ `int16[64][4][虚部, 実部]`（距離ビン × アンテナ）。リトルエンディアン、約 150 MB/時 |
| `radar_<セッションID>.hr.jsonl` | 2 秒ごとの推定 |

丸いボタンだけで測ったとき（課題なし）は、`radar_<UTC 日時>.*` だけができる。その間にストップウォッチで安静を測ると `rest_<UTC 日時>.json` が加わる: `t0` / `t1`（ストップウォッチの開始と終了。この PC の時計、ms）、`seconds`（長さ）、`planned`（目安の長さ）、`breaths` / `period_s`（その場で数えた呼吸の回数と長さの中央値）。

ネットワークに繋がっていれば、課題のセッションとイベントは Supabase にも送られ、ほかの PC のダッシュボードから見られる。繋がっていなければ、送らずにこの PC だけで進む。レーダーの生データ（`.bin`）は送らない。

### 時刻

課題中は、打鍵もレーダーも同じ時計（タイピング画面のローカル時刻）で記録する。課題の開始時に、アプリが自分の時計と画面の時計の差を測って合わせている（`radar_*.json` の `clockOffsetMs`）。その後はどちらも PC の同じ単調時計で進むので、打鍵とレーダーの間にずれは溜まらない。

UTC への換算は、Supabase に繋がっているときだけ課題の開始時と終了時に測り、`typing_*.json` の `syncs` に残る。換算の誤差は打鍵とレーダーに同じだけ乗るので、両者の前後関係には影響しない。

実測（88 秒の課題）: レーダーのフレームが PC に届くまでのゆらぎは中央値 4 ms、99% が 8 ms。レーダー内部の時計と PC の時計のずれは 88 秒で 1 ms。UTC への換算は開始時と終了時で 1.4 ms の差（往復遅延 125〜131 ms）。このほかに、フレームの処理と転送による一定の遅れが 15〜20 ms ある（見積もりで、測ってはいない）。

丸いボタンだけの記録は、この PC の時計のまま（同期なし）。

### `vital` と `breath`（`events.jsonl`）、`.hr.jsonl` の行

`vital` は 2 秒ごと、`breath` は 1 呼吸が終わるたびに 1 件。どちらも `data` は JSON 文字列で、`t` は打鍵と同じ時計。課題の入力は `session_start` から始まる。安静を課題の画面の中で測っていた版（0.3.0 まで）の記録には、安静の始まりと終わりに `baseline_start` と `baseline_end` が入っている。集計はどちらの形も読む。

| `vital` | `.hr.jsonl` | 意味 |
|---|---|---|
| `quality` | `quality` | 信号の質 0〜3。画面のバーと同じ。解析には 3 の行を使う |
| – | `quality_why` | その理由: `empty` / `static` / `moving` / `few` / `steady` |
| `present` | `present` | 呼吸している人が映っている（`snr` が 16 以上、かつ胸や背中の振れが 0.3 mm 以上） |
| `br` / `period` | `br_bpm` / `br_period_s` | 呼吸数（毎分）/ 直近 30 秒の呼吸の長さの中央値（秒） |
| `depth` | `br_depth_mm` | 呼吸の深さ（胸や背中の変位の振れ幅）の中央値 |
| `regular` | `br_q` | 波形の規則性（0〜1） |
| `moving` | `br_moving` | 直近 30 秒のうち、体そのものが動いていた割合 |
| `hr` / `q` | `hr_bpm` / `hr_q` | 心拍数（毎分）と、心拍の帯域の電力のうちその山の ±0.1 Hz に入る割合。`q` が 0.35 未満は使わない。`hr` が空のときは、呼吸の倍音と区別できなかった |
| `snr` | `snr_db` | 測っている距離の反射が雑音床より何 dB 強いか。胸なら 28〜39、背中なら 19〜29、何も映っていなければ 7〜13 |
| `range` | `br_range_m` | 測っている距離（m） |

`breath` は `t` がその呼吸の終わった時刻、`data` が `period`（長さ、秒）と `depth`（深さ、mm）。`.hr.jsonl` では各行の `breaths` に、直近 30 秒に終わった呼吸が同じ内容で入る。

## Python スクリプト

タイピング課題なしでレーダーだけ記録するとき、または解析に使う。

```
pip install pyserial numpy matplotlib
python radar/vitals.py                # Ctrl+C で終了
python radar/vitals.py --seconds 300  # 5 分で終了
```

`radar/captures` に `radar_<UTC 日時>.json / .bin / .hr.jsonl` ができる。

単独なので、時計は自分で合わせる。開始時と終了時にタイピング画面と同じ方式（[SPEC.md](../SPEC.md) §3.B）でずれを測り、`.json` の `syncs` に残す（`public/shared/clock.js` の `makeOffsetFn` にそのまま渡せる）。相手はローカルの実験サーバー（`node server/server.js`）、動いていなければ Supabase。別の PC のブラウザでタイピングさせて後で突き合わせるなら、そのブラウザと同じ相手に合わせる（`--backend server` / `--backend supabase`）。

`.bin` の読み方:

```python
import numpy as np
import vitals  # radar/vitals.py

rec = np.fromfile("radar_20261115-101247.bin", dtype=vitals.REC)
```

## 記録の様子を見る

```
python radar/report.py                      # radar/captures の全記録
python radar/report.py <.bin またはフォルダ>   # アプリの記録（ドキュメント/shinkokyu-radar）など
```

記録ごとに 1 行の要約を表示し、`.bin` の隣に `.report.png` を作る。呼吸は、記録に残った値ではなく、生データからいまの方法でやり直す。図は上から、反射の強さ（どの距離に物があったか）、動きの速さ、呼吸の波形（縦線が区切り、色の帯が体動）、1 呼吸ごとの長さ、心拍数（記録に残った値）、打鍵（課題中の記録のとき）。

| 列 | 意味 |
|---|---|
| `body m` | いちばん強い反射の距離 |
| `still` / `fast` | その距離の物がほぼ止まっていた / 速く動いていた時間の割合 |
| `seen` | 人が映っていた推定の割合 |
| `breaths` / `period` / `iqr` / `depth` | 区切れた呼吸の回数、長さの中央値、長さのばらつき（25〜75% の幅）、深さ |
| `moved` | 体そのものが動いていた時間の割合 |

課題中の記録では、打鍵していた時間の割合と、打鍵中とそれ以外での体動の割合・数えられた呼吸（毎分）も出る。

## 解析用の表にする

```
python radar/export.py              # このPCの「ドキュメント/shinkokyu-radar」
python radar/export.py <フォルダ>     # ほかの PC から持ってきたフォルダ
```

フォルダの中の全セッションを読み、`export/` に 2 枚の表を書く（UTF-8、Excel で開ける）。呼吸は、記録したときの値ではなく、レーダーの生データからいまの方法で求め直す。推定方法を直したあとも、全セッションが同じ扱いになる。

`sessions.csv`: セッションごとに 1 行。

| 列 | 意味 |
|---|---|
| `session_id` / `exp_id` / `participant_id` | セッション、課題、参加者 |
| `started_utc` / `synced` | 入力開始の時刻（UTC）。サーバーの時計と同期できたときだけ入る |
| `rest_s` / `rest_skipped` | 安静時の計測の長さ（秒）、目安より前に終えたか |
| `rest_breaths` / `rest_period_s` / `rest_period_iqr_s` / `rest_depth_mm` | 安静時: 呼吸の回数、長さの中央値、ばらつき（25〜75% の幅）、深さ |
| `rest_counted` | 安静時のうち、数えた呼吸が占める時間の割合。低いものは、数え落としが多いか、呼吸が浅すぎる・速すぎる区間が長い |
| `rest_moved` | 安静時に体が動いていた時間の割合。高いものは基準に使わない |
| `task_s` と `task_*` | 同じものの課題中の値 |
| `keys` / `final_chars` / `source_chars` / `finished` | 打鍵数、入力した字数、課題文の字数、最後まで終えたか |
| `radar_frames_dropped` | レーダーのフレームの欠落数 |

`breaths.csv`: 呼吸 1 回ごとに 1 行。

| 列 | 意味 |
|---|---|
| `phase` | `rest`（安静時）か `task`（課題中） |
| `t_s` | その呼吸が終わった時刻。入力開始からの秒（安静時は負） |
| `utc` | 同じ時刻の UTC（同期できたときだけ） |
| `period_s` / `depth_mm` | 長さ、深さ |

打鍵の速度や停止の指標は、ダッシュボードの書き出し（`sessions.csv` / `events.csv`）にある。`session_id` と時刻で突き合わせる。

保管は「ドキュメント/shinkokyu-radar」をフォルダごと残す。生データ（`typing_*`、`radar_*`、`rest_*`）が元で、`export/` と `.report.png` はいつでも作り直せる。

## 胸ストラップと比べる

心拍数が合っているかは、胸ストラップ（拍ごとの間隔を出す Bluetooth 心拍計。Polar H9/H10、Garmin HRM-Dual、Wahoo TICKR など）を同時に記録して確かめる。

```
pip install bleak
python radar/vitals.py --strap --seconds 300   # レーダーとストラップを同時に記録
python radar/strap.py                          # ストラップだけ（アプリで測るときに並べて動かす）
```

ストラップは先に身に着け（肌に触れると電源が入る）、スマートフォンのアプリとの接続は切っておく。PC の Bluetooth はオンにする。拍ごとの間隔が `.rr.jsonl` に 1 秒ごとに追記される。`report.py` は、`.bin` と同じ名前の `.rr.jsonl` があれば、図にストラップの心拍数を重ね、要約の `vs strap` に差（平均絶対差、毎分）を出す。実物のストラップでは試していない。

## 呼吸ベルトと比べる

呼吸が合っているかは、胸に巻いたひずみゲージ（Arduino の A0 につなぎ、`time_s,raw_value,...` の行を 115200 bps で毎秒 50 行送るもの）を同時に記録して確かめる。

```
python radar/vitals.py --belt --seconds 180   # レーダーとベルトを同時に記録
python radar/belt.py                          # ベルトだけ（アプリで測るときに並べて動かす）
```

`.belt.csv` に、届いた時刻（レーダーのフレームと同じ時計、ミリ秒）・Arduino 側の時刻・A0 の値が 1 行ずつ追記される。`report.py` での突き合わせはまだ無い。

## 測定の仕組み

1 フレームは 0.75 ms 間隔の 16 チャープで、毎秒 40 フレーム。ファームウェアが出すのは 16 チャープの和（速度ゼロの成分）なので、約 8 cm/s より速く動くもの（キーを打つ手や腕）は打ち消され、胸（2 cm/s 未満）が残る。送信は 77.0〜80.82 GHz（ARIB STD-T111 の 77〜81 GHz の内側）、送信アンテナは 1 本。

胸の動きを 1 本の信号として追い、そこから呼吸と心拍数の両方を出す（[breathing.py](breathing.py)、アプリでは `app/src-tauri/src/breathing.rs`）。胸の変位を時間の長さで 3 つに分ける。広いガウシアンが追う成分が姿勢、その上で狭いガウシアンが追う成分が呼吸、残りに心拍が入っている。

1. 同じ距離に動かない強い反射（背中側から測るときの背もたれ、机の縁など）があれば取り除く。動く反射は複素平面で円弧を描き、その中心が動かない反射にあたる。残したままだと位相の振れが縮む。
2. 距離ビンごとに、フレーム間の位相差から胸の速度を出す。呼吸ではありえない速さ（25 mm/s 超）は位相の飛びとして切り落とす。
3. 積分して変位にし、ガウシアン（σ 0.35 秒）で平滑化して雑音と心拍を落とし、広いガウシアン（σ 2.5 秒）で求めた基線を引いて姿勢のずれを落とす。残ったものが呼吸の波形。
4. 雑音床より 16 dB 以上強い距離ビンのうち、いちばん強く動いている反射を体の位置とする。後ろの壁や家具は体より強く反射することがあるが、動かない。そこから ±0.25 m 以内で、波形がいちばん規則的に繰り返すビンを胸とみなし、同じ動きをする隣のビンとまとめる。反射がいちばん強い距離が胸とは限らない。
5. 波形の下がりと上がりの 1 組を 1 呼吸とする。波形は胸までの距離なので、下がりが吸う側にあたる。上がり・下がりは、直近 30 秒の振れのうち大きいほう（75 パーセンタイル）の 3 割以上あるものだけを数える（呼吸信号の区切り方として使われている Schäfer & Kratky 2008 の規則。レーダーの波形はさざ波が多いので割合を 2 割から 3 割に上げてある）。深く吐いたあとの休止に乗る小さな揺れは数えず、浅い呼吸しかないときはその浅い振れを数える。波形がゼロに戻るかどうかは見ない。体の位置のずれが残っていても区切れる。1 呼吸の境目は、下がりの中ほど（山と谷の中間の高さを切るところ）、つまり吸っている途中に置く。呼吸ベルトと比べると、吸う側に置いたほうが吐く側より一致した（34 回中 27 回と 22 回）。1.7 秒より短い呼吸（毎分 35 回超）は数えない。その速さの浅い呼吸は、胸の心拍の動きと大きさも速さも重なり、この波形では区別できない。体そのものが動いている区間（0.5 秒平均で 12 mm/s 超）は数えない。
6. 心拍数は呼吸のあとに、呼吸を優先して決める。呼吸の平滑化で取り除かれた残り（速度に直したもの）の直近 20 秒のスペクトルを使い、0.8〜2.5 Hz の各周波数を、その 2 倍の周波数の強さと合わせて評価する。前回の値から ±10 以内に、最大の山の半分以上の強さの山があればそちらを取る。選んだ山が測った呼吸数の 2〜5 倍に当たるときは、直前までそこが心拍数だった場合だけ心拍数として残し、そうでなければその時点の心拍数は出さない。

手順は同じ機材を使った Hao ほか「mmWave-RM」（Sensors 2024, [doi:10.3390/s24134315](https://doi.org/10.3390/s24134315)）と同じ系統。関連研究は [docs/survey/radar-vitals.md](../docs/survey/radar-vitals.md)。

## 確認できていること

- 正面から、じっと座って普通の呼吸: 約 3 秒周期・深さ 2 mm で区切れる。生の変位のスペクトルが毎分 20〜22 回を示す 37 秒間に 11 回、長さの中央値 3.0 秒（毎分 20 回）。
- 正面から、じっと座って深呼吸: 中央値 6 秒・深さ 3 mm で区切れ、長さのばらつき（25〜75% の幅）は 1.5 秒。
- 呼吸ベルト（胸に巻いたひずみゲージ）との同時記録、正面 0.45 m、1 人、3 分（呼吸の区切りの数で比べた）: ベルト 34 回に対しレーダー 32 回。同じ呼吸（区切りが 1 秒以内）は 27 回、ベルトにあってレーダーにない 7 回、レーダーだけ 5 回。長さの中央値はベルト 4.1 秒、レーダー 3.9 秒。落ち着いていた後半 72 秒は 17 回中 15 回が一致した。前半には姿勢を直す動きがあった。この記録では、体（25〜27 dB）より 1.4 m 先の壁（28〜29 dB）のほうが強く反射していた。
- 同じベルトで、真横（肋骨の横、0.4 m）から 3 分: ベルトは毎分 24 回の呼吸を示したが、レーダーの波形との一致は偶然の水準で（0.24〜0.76 m の全距離でコヒーレンス 0.17 以下）、数えた 18 回のうちベルトと合ったのは 9 回だった。それでも表示は 3 本だった。
- 何も映っていないとき（反射 7〜13 dB）と、椅子だけが映っているとき（反射 36 dB、動き 0.01 mm）は、どちらも「人が映っていない」になる。
- アプリと Python スクリプトは、同じ `.bin` から同じ推定値を出す。
- 課題中、打鍵とレーダーは同じ時計で記録される（上の「時刻」の実測）。
- アプリは、レーダーを繋いで、向き合わせ → 安静時の計測（3 分）→ 課題 → 終了までを通し、打鍵・`vital`・`breath` とレーダーの生データがこの PC に残ることを確かめた（背中側、Supabase あり）。

## 確認できていないこと

- 数えた呼吸が実際の呼吸と合っているか。呼吸ベルトとの照合は 1 人・正面・3 分の 1 本だけで、打鍵中、背中側、ほかの人では比べていない。ベルト自体も、深い呼吸のあと値がゆっくり戻る間は次の呼吸を小さく写す。区切りのしきい値（振れの 3 割）を 2.5 割にすると、この 1 本ではベルトとの一致が 27 → 30 回に増えるが、基準のないほかの記録でも回数が 5〜10% 増える。1 本では決められないので 3 割のままにしてある。
- 呼吸が映っていないのに 3 本になる場合を見分けること。真横からの記録では、体のゆっくりした揺れを呼吸として数えた。
- 浅く速い呼吸。意図して小刻みにした呼吸（生の変位で毎分 43〜47 回、振れ 0.8〜1.1 mm）は数えられない。深い呼吸や大きな動きの直後 30 秒は、しきい値が上がって浅い呼吸を落としやすい。背中に向けた 32 秒（振れ 0.5〜1 mm）では 2 回しか区切れなかった。
- 背中側からの計測で、呼吸が正しく区切れているか。背中に向けた記録は 1 本（安静 3 分 + 打鍵 1 分）で、反射は 19〜29 dB、深さは 0.8〜3 mm だった。判定のしきい値はこの 1 本に合わせて下げたもので、ほかの人や椅子では確かめていない。
- 体が動いている間（手書きの課題など）。正面から測った 5 分の記録では、区切れた呼吸は毎分 5 回ほどで、実際の 3 分の 1 程度だった。
- 心拍数の正しさ。静止時に 68〜78 の範囲で安定して出るが、基準と比べていない。
- 体動のしきい値（12 mm/s）。深く速く吸う呼吸を体動と取り違えないかは確かめていない。
- 3 本になる条件（2 回以上区切れる、体動 2 割以下）が妥当か。背中側の 1 本では、安静時の 40% が 3 本、40% が体動だった。
- macOS での動作。別の PC での動作。

## 開発

```
python radar/test_vitals.py                 # Python の自己チェック（レーダー不要）
node tools/e2e.mjs <作業用フォルダ>           # タイピング画面の E2E。アプリとの受け渡しも見る（要 node server/server.js）

cd radar/app
npm ci
npx tauri dev                               # アプリを起動
cd src-tauri
cargo test
cargo run --release --example headless -- replay <file.bin>          # 保存した .bin から推定
cargo run --release --example headless -- record 60 <出力先の接頭辞>   # 画面なしで 60 秒記録
```

`radar-v0.3.0` のようなタグを push すると、GitHub Actions が Windows と macOS のインストーラーを作り、Release の下書きに付ける。
