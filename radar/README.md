# レーダー計測（非接触の心拍・呼吸）

79GHz 帯レーダー評価キット PTM RFR79ITR34-30U（TI IWR1843 搭載）で、座っている人の心拍数と呼吸数を測り、タイピング実験と一緒に記録する。

- デスクトップアプリ [app/](app/)（Tauri。Rust + TypeScript、Windows / macOS）: タイピング課題とレーダー計測を 1 つのアプリで行う
- Python スクリプト [vitals.py](vitals.py): レーダーだけを単独で記録する

チャープ設定（[chirp.cfg](chirp.cfg)）と推定方法は共通。

## 用意するもの

- レーダー本体と USB Type-C ケーブル。給電も USB。同梱の DA ボードは使わない。
- ファームウェアは出荷時のまま（mmWave SDK 3.5 のデモ）。
- PC にはシリアルポートが 2 つ現れる（FTDI FT4232H）。現れない場合は FTDI の VCP ドライバを入れる。ポート番号の指定は要らない。

## 置き方

- レーダーは三脚とクランプで固定し、ケーブルも動かないように留める。ケーブルが揺れると USB 接続が切れる。切れても自動で繋ぎ直し、記録は続く。
- 胸の正面、0.5〜0.8 m。測れるのは 0.3〜1.5 m。
- 上下方向のビームは ±10° ほどしかない。0.6 m 先で上下 ±10 cm なので、高さを胸骨に合わせる。左右は ±50° ほどと広い。

## 動作確認の手順（アプリ）

1. [Releases](https://github.com/Suke-go/shinkokyu/releases) からインストーラーを取って入れる（Windows は `.exe`、macOS は `.dmg`）。署名はしていないので、初回は Windows なら「詳細情報 → 実行」、macOS なら右クリック →「開く」。
2. レーダーを繋ぎ、アプリを開いて丸いボタンを押す。輪が一周するまでの 20 秒はデータを溜めている。
3. 椅子にもたれてじっとし、レーダーの高さと向きを直す。見るのは次の 2 つ。
   - ボタンの上の帯: いまレーダーに映っているもの。左が近く（0.3 m）、右が遠く（1.5 m）で、濃いほど強い反射。自分の距離のところが濃くなるように向ける。0.5 秒ごとに更新される。
   - 大きい数字（心拍数、毎分）: 濃く表示されて落ち着けばよい。下の数字は呼吸数、線は胸の変位（直近 20 秒）。数字が薄い間は推定が信用できない（体が動いている）。数字が出ず「–」のままなら、人が映っていない（何も映っていないか、映っているのが椅子や壁のような呼吸しない物）。
4. 鉛筆のボタンでタイピング課題を開く。実験 ID（試すだけなら `demo-ja`）と参加者 ID を入れて進める。
5. 入力画面の下端のハートが濃い間は、人が映っていて、推定がその課題の記録に入っている。薄い間は人が映っていない。
6. 終わったら、グラフのボタンでダッシュボードを開き、いまのセッションが一覧にあることを確かめる。

## 記録されるもの

アプリでは、時刻合わせも保存の確認もタイピング課題の 1 回分で済む。

- 2 秒ごとの推定値は、打鍵と同じイベント列に `type: "vital"` として入り、同じ送信経路で保存される。`t` は打鍵と同じ時計（タイピング画面のローカル時刻）なので、そのセッションの時刻同期の結果で一緒に補正できる。`data` は JSON 文字列。

  | キー | 意味 |
  |---|---|
  | `hr` / `br` | 心拍数 / 呼吸数（毎分）。`t` までの 20 秒間についての値 |
  | `present` | 人が映っている（`snr` が 26 以上、かつ `span` が 0.5 以上）。false の行は使わない |
  | `q` | 心拍帯域の電力のうち、ピーク ±0.1 Hz に入る割合。0.35 未満の行は使わない |
  | `snr` | 測っている距離の反射が雑音床より何 dB 強いか。体なら 28〜39、何も映っていなければ 7〜13 |
  | `span` | 呼吸帯域での胸の変位の振れ幅（mm）。人なら数 mm、椅子や壁なら 0.2 未満 |
  | `range` | 測っている距離（m） |

- 生データは大きいので PC に残す。「ドキュメント/shinkokyu-radar」に `radar_<セッションID>.*` ができる。丸いボタンだけで測ったとき（タイピング課題なし）も同じ場所に `radar_<UTC 日時>.*` として残る。

  | ファイル | 中身 |
  |---|---|
  | `.json` | チャープ設定、フレームレート、セッション ID |
  | `.bin` | 全フレーム。固定長レコード: 到着時刻 `float64`（ms）、フレーム番号 `uint32`、IQ `int16[64][4][虚部, 実部]`（距離ビン × アンテナ）。リトルエンディアン、約 150 MB/時 |
  | `.hr.jsonl` | 2 秒ごとの推定（`present`, `hr_bpm`, `hr_q`, `br_bpm`, `snr_db`, `span_mm`, `range_m`, `hr_harmonic`） |

  時刻は、課題中の記録ではタイピング画面のローカル時刻、丸いボタンだけの記録ではこの PC の時計（同期なし）。

アプリの中のタイピング課題は GitHub Pages 版と同じもので、保存先は Supabase。

## Python スクリプト

タイピング課題なしでレーダーだけ記録するとき、または解析に使う。

```
pip install pyserial numpy matplotlib
python radar/vitals.py                # Ctrl+C で終了
python radar/vitals.py --seconds 300  # 5 分で終了
```

`radar/captures` に、アプリと同じ形式の `radar_<UTC 日時>.json / .bin / .hr.jsonl` と、最後の 20 秒の波形 `.png` ができる。

単独なので、時計は自分で合わせる。開始時と終了時にタイピング画面と同じ方式（[SPEC.md](../SPEC.md) §3.B）でずれを測り、`.json` の `syncs` に残す（`public/shared/clock.js` の `makeOffsetFn` にそのまま渡せる）。相手はローカルの実験サーバー（`node server/server.js`）、動いていなければ Supabase。別の PC のブラウザでタイピングさせて後で突き合わせるなら、そのブラウザと同じ相手に合わせる（`--backend server` / `--backend supabase`）。

`.bin` の読み方:

```python
import numpy as np
import vitals  # radar/vitals.py

rec = np.fromfile("radar_20261115-101247.bin", dtype=vitals.REC)
```

## 記録の様子を見る

```
python radar/report.py                      # radar/captures の全記録
python radar/report.py <.bin またはフォルダ>   # アプリの記録（ドキュメント/shinkokyu-radar）など
```

記録ごとに 1 行の要約を表示し、`.bin` の隣に `.report.png` を作る。図は上から、反射の強さ（どの距離に物があったか）、動きの速さ、推定値、信頼度。人が映っていなかった区間は灰色の帯になる。

| 列 | 意味 |
|---|---|
| `body m` | いちばん強い反射の距離 |
| `still` / `fast` | その距離の物がほぼ止まっていた / 速く動いていた時間の割合 |
| `seen` | 人が映っていた推定の割合 |
| `usable` | 使える推定（人が映っていて `q` が 0.35 以上）の割合 |
| `HR` / `spread` | 使える推定の心拍数の中央値 / ばらつき（10〜90% の幅） |

## 測定の仕組み

1 フレームは 0.75 ms 間隔の 16 チャープで、毎秒 40 フレーム。ファームウェアが出すのは 16 チャープの和（速度ゼロの成分）なので、約 8 cm/s より速く動くもの（キーを打つ手や腕）は打ち消され、胸（2 cm/s 未満）が残る。

体が写っている距離ビンと 4 本の受信アンテナをまとめて、フレーム間の位相差を求める。位相差は胸の速度、その累積は変位（1 周で波長の半分、約 1.9 mm）。呼吸数は変位の 0.1〜0.6 Hz、心拍数は速度の 0.8〜2.5 Hz のスペクトルのピークから求める。

人が映っているかは、反射の強さと動きの両方で決める。測っている距離の反射が雑音床（何も映っていない距離の反射）より 26 dB 以上強く、かつ呼吸の帯域で 0.5 mm 以上動いていること。強いだけなら椅子や壁、動いているだけなら雑音である。

送信は 77.0〜80.82 GHz（ARIB STD-T111 の 77〜81 GHz の内側）、送信アンテナは 1 本。

## 確認できていること

- Python スクリプトで、静止して座った状態の心拍数が 68〜73 bpm の範囲に 20 秒ほど安定して出る。
- パルスオキシメーターなどの基準との照合はしていない。
- 姿勢を変えたり前に乗り出したりしている間は推定が外れる。その区間は `q` が下がる。
- 呼吸数は心拍数より安定しない。
- アプリと Python スクリプトは、同じ `.bin` から同じ推定値を出す。
- 何も映っていないとき（反射 7〜13 dB）と、椅子だけが映っているとき（反射 36 dB、動き 0.01 mm）は、どちらも「人が映っていない」になる。
- アプリは、レーダーを繋いで向き合わせの画面（帯と推定値の表示）まで確かめた。レーダーを繋いだままタイピング課題を最後まで通すことと、macOS での動作は確かめていない。

## 開発

```
python radar/test_vitals.py                 # Python の自己チェック（レーダー不要）
node tools/e2e.mjs <作業用フォルダ>           # タイピング画面の E2E。アプリとの受け渡しも見る（要 node server/server.js）

cd radar/app
npm ci
npx tauri dev                               # アプリを起動
cd src-tauri
cargo test
cargo run --release --example headless -- replay <file.bin>          # 保存した .bin から推定
cargo run --release --example headless -- record 60 <出力先の接頭辞>   # 画面なしで 60 秒記録
```

`radar-v0.2.0` のようなタグを push すると、GitHub Actions が Windows と macOS のインストーラーを作り、Release の下書きに付ける。
